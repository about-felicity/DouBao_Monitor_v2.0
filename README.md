# 多模型监控系统（豆包 × 元宝 × DeepSeek）

DeepSeek 已接入统一模型注册表、采集控制、逐日统计、信源和运行明细。完整链路为：发送前记录网页最新会话 ID，问题只从 MuMu DeepSeek App 发送，等待 App 回答稳定且恢复输入状态后，再等待网页端出现新的同问题会话，确认网页回答与链接数量稳定，自动展开“多个网页”信源面板并采集全部唯一信源。空回答、系统异常、同步超时或旧会话均跳过且不写入有效统计。首次使用需同时登录 App 和启动按钮自动打开的专用网页（也可手动运行 `deepseek_monitor/open_deepseek_chrome.bat`）；采集默认强制使用 60–600 秒随机提问间隔，等待窗口会写入本地状态，任务重启后仍然有效。

从统一面板启动 DeepSeek 时会立即显示启动阶段，并自动创建或唤醒专用 Chrome、校验模拟器与网页账号；校验通过后才启动采集脚本。

豆包与腾讯元宝 MuMu 多设备循环提问、网页端同账号抓取、北京时间归档、品牌与竞品分析及统一 React 实时面板。

系统通过 `model_plugins/<model-id>/plugin.py` 自动发现模型。采集、问题配置、账号校验、分析和数据文件均由模型插件隔离；新增模型不需要修改现有模型代码或前端静态注册表。

## 统一面板

双击根目录 `一键启动三模型监控.bat`，浏览器会打开：

<http://127.0.0.1:3000/>

统一面板包含：

- 全部模型或任意单模型的数据范围；
- 模型总览、同问题跨模型比较、信源洞察、回答审计和采集控制；
- 问题与北京自然日筛选；
- 每个模型独立的问题清单、账号一致性校验、轮数和启停状态；
- 豆包采集控制卡提供每 3 秒刷新的实时回传日志，可查看处理中、已入库、异常和逐条信源写入数；
- 每个问题当日的文章/视频信源 Top 10，以及两类信源独立的标题文案关键词。

本地数据 API 使用 `8765` 端口，React 界面使用 `3000` 端口，豆包局域网接收器使用 `8790` 端口。

## 远端豆包回传

豆包只在另一台电脑运行；元宝与 DeepSeek 在面板电脑本机运行。主电脑启动后会生成：

`doubao_mumu_controller/doubao_lan_pairing.json`

远端豆包电脑需要先拉取最新代码，然后把该配对文件复制过去。可把配对文件直接拖到 `doubao_mumu_controller/远端豆包一键配置回传.bat` 上完成配置。此后抓取进程只负责把有效结果原子写入远端待传队列，不执行网络请求；独立同步代理每 5 秒通过带令牌的局域网接口回传。主电脑先把数据原子写入接收队列，再快速返回带相同 `request_id` 的确认；远端只有核对确认成功才移出待传队列。超时、断线或错误确认均不会阻塞采集，数据会保留并自动重传。配对文件和真实令牌不会提交到 Git。

## 模块边界

- `model_plugins/`：每个模型的元数据、问题配置、账号校验和启动命令。
- `deepseek_monitor/`、`yuanbao_monitor/`、`doubao_mumu_controller/`：模型专属采集实现。
- `monitor_core/quality.py`：统一识别空回答、过短回答和系统异常；无效轮次直接跳过且不进入信源统计。
- `monitor_core/analytics.py`：只读取标准化运行记录，生成跨模型比较、Top 10 和关键词。
- `doubao_dashboard_server.py`：统一 API 与进程编排，不包含具体模型抓取逻辑。
- `yuanbao_monitor/dashboard/`：只消费模型目录和分析 API，新增模型自动显示。

## 一键部署

1. 安装 Google Chrome、MuMu 模拟器和 Python 3.11 以上版本。
2. 启动需要使用的 MuMu 实例，并在每个实例的豆包 App 中登录账号。
3. 双击根目录的 `一键部署并启动.bat`。部署程序会检查并安装
   Appium、UiAutomator2 和 Java；MuMu 自带的 ADB 会自动适配为 Appium
   可识别的 Android SDK 目录。
4. 程序会为每个 MuMu 实例建立独立的调试 Chrome。首次运行时，在各 Chrome 中登录对应的豆包账号，然后回到控制面板点击“重新检测账号”。
5. 两端账号匹配后即可开始循环提问。

本地实时面板默认地址：<http://127.0.0.1:3000/>

新克隆的项目不会附带任何已采集结果，首次启动从空数据开始。仓库中的历史示例位于 `sample_data/`，面板不会自动读取该目录。

## API Key

真实密钥仅保存在：

`doubao_mumu_controller/doubao_api_keys.env`

仓库只提供 `doubao_api_keys.env.example`。首次一键部署会自动复制模板；如需未命中品牌词库时调用大模型兜底，请在本机密钥文件中填写自己的 Key。

## 品牌词库

自有品牌和竞品配置保存在 `doubao_brand_settings.json`，会随项目提交。也可以在 MuMu 控制面板的“自有品牌与竞品”页签中维护。

## 多设备规则

- 动态识别当前已启动的 MuMu 实例数量。
- 每个 MuMu 实例对应独立豆包 App 账号、独立 Chrome 用户目录和独立调试端口。
- 所有设备数据写入同一套本地数据文件，可在面板切换单设备或查看全部设备汇总。
- 采集结果、内容缓存和运行计数仅保存在当前电脑，不受 Git 跟踪，也不会随 `git pull` 覆盖。
- 豆包远端结果上传到主电脑；元宝和 DeepSeek 仍只在主电脑本地读写。

## 安全说明

GitHub 仓库不应包含真实 API Key、Cookie、Chrome 登录目录、账号令牌或局域网配对令牌。`.gitignore` 已排除这些文件；部署到新电脑后需在该电脑自行登录豆包并配置密钥。
